# Toscanini Design Review

Inspect relevant screens, components, tokens, and authoritative design documentation. Reuse existing primitives before proposing new ones. Cover responsive behavior, accessibility, loading, empty, validation, error, permission, offline or network failure, and destructive states.

For review, use an independent context and browser evidence when available. Report concrete mismatches and conclude with `APPROVE` or `REQUEST_CHANGES`.
