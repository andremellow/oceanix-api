## Findings

### TA-01 — No executable regression for expanded input identity after reorder

- Severity: high; classification: in-contract; blocking: yes.
- Basis: AC-03 and INV-01; frozen surface `Expanded lesson controls and focus after reorder`, QA-03.
- sourceRole: `test-analyst`; failureStage: `test-implementation`; discovery round: 1; phase: review.
- Evidence: component lines 1071, 1117 and 1142 add/revise keys controlling real Livewire/Alpine node replacement. `CourseEditorTest.php` around lines 540–594 checks ordered server IDs and a focus event; it does not populate expanded nested controls then edit them after reorder. JavaScript lines 88–103 supplies already-correct IDs to `markDirty`, without mounting controls, morphing nodes, executing the new keys, restoring focus or saving a moved record. An in-memory experiment removed every lesson-fields/question/option key from the source consumed by the JavaScript suite: all 11 tests still passed, exit 0. No files were changed in this experiment.
- Required outcome: add an executable browser/DOM integration regression using the installed binding/morph runtime and three distinctly populated expanded lessons with nested questions/options. Reorder in both directions, assert actual displayed control values against stable IDs and contextual focus, edit the moved lesson and a nested answer, then verify fresh persistence/reload changes only the intended IDs. The test must fail when the positional reuse fix is removed. Reuse the frozen QA-03 fixtures and scenario; this requests no additional product scenario. Source-key assertions or another server-only reorder test cannot prove this fix.

### TA-02 — Cancellation regression test never exercises cancellation

- Severity: medium; classification: in-contract; blocking: yes.
- Basis: AC-02, specifically cancelled confirmations must not create pending state; frozen surface `Module request dispatch/failure/retry`, QA-02's cancellation control.
- sourceRole: `test-analyst`; failureStage: `test-implementation`; discovery round: 1; phase: review.
- Evidence: JavaScript lines 125–130 labels the test “search and cancelled confirmation” but calls only `request('moduleSearch')`. No removal control, confirmation callback, rejection, or accepted-confirmation positive control executes. The test proves only that an unlisted action leaves clean state. PHP checks the lesson `wire:confirm` attribute but cannot execute it. Installed Livewire runtime lines 16153–16190 runs the confirmation before evaluating the action; the new action interceptor depends on that boundary, which the test manually assumes.
- Required outcome: exercise the actual confirmation-to-action boundary for the existing confirmed removal control: decline and assert no mutation request and unchanged clean/pending/revision state; accept as a positive control and assert mutation dispatch enters pending. An isolated test executing the installed confirmation/action directive and production interceptor is sufficient if it preserves their real ordering; browser automation is also suitable. Do not add a new confirmation to an unconfirmed control merely to satisfy the test.
