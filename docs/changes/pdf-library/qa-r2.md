## Blocking finding QA-R2-01

- Detector / sourceRole: QA / qa.
- failureStage: implementation.
- Discovery: round 1, phase qa, independent at `pdf-library-20260916-r2`.
- Severity: medium; blocking.
- Scope/classification: in-contract, IMPLEMENTATION_DEVIATION.
- Basis: approved AC-06 and INV-04; FR-008, B-14 / QA-07; design state contract “List/network failure” requires an error and Try again while retaining editor state. Architecture §8 requires preserving authored text and retry for operational failures. This is an approved acceptance failure, not a claim about causal regression inferred from source code.

Reproduction:

1. Sign into the disposable company editor as the synthetic admin. Type ` QA transport pending` into the current content editor and allow updates to settle.
2. Positive control in a fresh page with the same unsaved marker: Save changes and Insert PDF both report enabled; normal Insert PDF opens the populated modal and preserves exact HTML. Evidence: `/tmp/oceanix-pdf-qa-6Lsaog/qa-07-positive-open.png`.
3. On the failing page, intercept only the next Livewire request whose actual payload calls `openPdfModal`, and abort that transport request. The recorded method list was exactly `["openPdfModal"]`; this was not a selector timeout or an unrelated background request.
4. After settling, no PDF dialog exists; editor HTML still contains exactly the unsaved marker, but Insert PDF and Save changes both report disabled. The page announces an unknown outcome and that automatic retry is unavailable.
5. “Reload latest draft” opens a dialog stating that it will replace unsaved values, with “Keep my unsaved values” and “Reload and discard local values.” Choose Keep. Exact unsaved HTML remains, but Save and Insert PDF remain disabled. There is no usable preserving retry from the offered UI.

Expected: a failed initial PDF-modal/library read must preserve the editable draft and provide retry/recovery without requiring the user to discard authored changes. Observed: content remains in memory but cannot be saved or used to retry the PDF action; the offered recovery discards it. No discard was accepted.

Evidence screenshot: `/tmp/oceanix-pdf-qa-6Lsaog/qa-07-initial-request-recovery.png`. Required outcome: recover from interrupted initial PDF opening/list load while retaining unsaved content and usable editing/Save, with a retry that reaches the modal; retain passing search/reuse/archive transport behavior. No implementation remedy is prescribed by QA.
